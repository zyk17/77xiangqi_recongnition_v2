# 第三版棋盘定位执行计划

## 1. 目标

这份文档只解决一个问题：

```text
第三版棋盘定位应该如何落地执行
```

协作方式保持不变：

- 你负责实现、训练、实验推进
- 我负责 review、失败分析、方案收口

这不是长期方案复盘文档，而是当前版本的实施计划。

## 2. 当前共识

在进入第三版前，已有结论如下：

- 第一版 `bbox -> 均匀切 9x10` 已失败
- 第二版 `geom[19] + types[90]` 已失败
- 继续优化第二版的 epoch、loss 权重、轻微增强，不太可能从根本上解决问题
- 第三版必须让模型先学习局部空间证据，再恢复棋盘坐标系

因此第三版主线明确为：

```text
image -> evidence maps -> grid recovery -> 90 cells -> piece_classifier
```

## 3. 第三版范围

第三版先做最小可行闭环，不一次做满所有想法。

本轮只包含：

- 重新定义标签输出为证据图
- 基于现有合成链生成第三版训练数据
- 做一个最小模型跑通训练
- 做一版轻量 grid recovery
- 接回现有 `piece_classifier`
- 用真实 `eval_cases` 判断方向是否成立

本轮不做：

- 复杂多分支网络堆叠
- 自由候选点 + 重几何后处理
- 新的棋子分类器
- Rust 端正式实现
- 过度追求速度优化

## 4. 第三版输出定义

### 4.1 推荐第一版输出

第三版的最小输出先收口成 2 到 3 张空间图：

- `piece_map`
- `cross_map`
- 可选 `line_map`

建议优先级：

1. 先做 `piece_map + cross_map`
2. 如果恢复不稳，再加入 `line_map`

原因：

- `piece` 监督最强
- `cross` 能补空点
- `line` 有助于约束网格，但先不把问题复杂化

### 4.2 不再直接输出

第三版不再直接让模型输出：

- `x[9]`
- `y[10]`
- `types[90]`

这些量可以作为恢复结果，但不应是模型唯一直接输出。

## 5. 标签定义

### 5.1 输入来源

继续复用当前已完成的：

- `grid_roi.json`
- `grid_points`
- `piece/cross` 标签

也就是说，第三版标签不需要重新人工标注。

### 5.2 训练标签

每张训练图生成：

- `piece_map`
  - 在 `piece` 交点位置画高斯点
- `cross_map`
  - 在 `cross` 交点位置画高斯点
- 可选 `line_map`
  - 在主棋盘有效线段位置画线响应

建议：

- 输出分辨率先用输入的 `1/4`
- 高斯半径按局部 `dx/dy` 自适应
- `piece` 与 `cross` 分开监督，不共用一个通道

### 5.3 非棋盘区域

棋盘外所有元素继续只作为背景：

- 圆形头像/按钮
- 文字
- UI 面板
- 背景插画
- 表格感结构

这些内容不做正标注。

## 6. 数据生成计划

### 6.1 保留

继续保留：

- `grid_roi` 驱动的交点推导
- `piece/cross` 语义
- 棋盘外 UI 干扰
- 不同棋盘主题
- 不同棋子皮肤
- 中残局 / 随机布局

### 6.2 继续禁用

继续禁用：

- 小棋盘 / 副棋盘增强
- 棋盘内部遮挡增强

### 6.3 需要新增

第三版数据层必须补的不是新标注，而是更接近真实的棋盘外背景复杂度：

- 背景图
- 人物/角色立绘
- 顶部信息条
- 底部操作栏
- 半透明层
- 图标密集区

目标不是“故意刁难模型”，而是让训练分布更接近真实截图。

## 7. 模型建议

### 7.1 第一版骨架

第三版最小模型建议：

- 继续用小骨架
- 输出 2 或 3 个通道的空间图

可以接受：

- `MobileNetV3-Small + 上采样 head`
- 轻量 U-Net 风格 decoder
- 小 FPN 式 decoder

要求：

- 足够轻
- 容易导出 ONNX
- 输出空间图稳定

### 7.2 不要一开始做的事

先不要一开始就做：

- 太深的 decoder
- 多任务大杂烩
- attention 堆叠
- 很多辅助损失同时上

目标是先证明“空间证据图路线是对的”。

## 8. Loss 建议

第三版第一轮 loss 建议：

- `piece_map_loss`
- `cross_map_loss`
- 可选 `line_map_loss`

首选方向：

- heatmap BCE / focal 类损失
- 必要时对正样本做加权

建议先避免：

- 过重的结构损失
- 复杂对比学习损失
- 很多手工规则同时加进去

第三版第一阶段先证明：

- 模型确实能在图上响应真实 `piece/cross`

## 9. Grid Recovery 建议

### 9.1 目标

恢复逻辑必须轻量，但可以存在。

它的作用是：

- 从 `piece_map/cross_map(/line_map)` 中恢复唯一主棋盘坐标系

### 9.2 原则

允许做：

- 轻量峰值提取
- 行列一致性约束
- 基于主棋盘结构的唯一恢复

不允许做：

- 大量自由候选点 + 重聚类
- 复杂传统几何拼装
- 把模型问题全部甩给后处理

### 9.3 第一版恢复目标

第一版 grid recovery 的成功标准不是“理论最优”，而是：

- 在真实 `eval_cases` 上明显优于第二版
- 能稳定产生可裁 90 格的坐标系

## 10. Pipeline 接回计划

第三版参考 pipeline 目标：

```text
image
-> board localization model
-> evidence maps
-> grid recovery
-> 90 cell bboxes
-> piece_classifier
```

当前 `piece_classifier` 先不动。

如果第三版失败，优先怀疑：

- board localization
- recovery

不要过早怀疑棋子分类器。

## 11. 里程碑

### M1 标签和数据

完成标准：

- 第三版标签生成逻辑实现完成
- 可生成 `piece_map/cross_map`
- 抽样 overlay 可人眼确认

### M2 最小训练

完成标准：

- dataset 可读
- 前向可跑
- smoke 训练通过
- loss 明显下降

### M3 证据图可视化

完成标准：

- 能对 train/val/real case 输出 `piece_map/cross_map` 可视化
- 能明显看出模型在响应真实点，而不是只猜模板

### M4 整链评估

完成标准：

- 接回 `piece_classifier`
- 跑真实 `eval_cases`
- 指标明显优于第二版

### M5 是否继续扩展

分支判断：

- 如果第三版明显有效，再考虑加 `line_map`
- 如果第三版仍然学成模板，再回头调整任务定义和数据分布

## 12. 建议实施顺序

建议你按这个顺序做：

1. 标签生成改成 `piece_map/cross_map`
2. 抽样生成 overlay，自查 20 张
3. 实现最小模型
4. 跑 smoke train
5. 导出证据图可视化
6. 做第一版 grid recovery
7. 接回 `piece_classifier`
8. 跑真实 `eval_cases`
9. 再决定是否上 `line_map`

## 13. 我 review 的重点

你开始实现后，我会重点看：

- 标签是否真的对应 `piece/cross` 空间证据
- 数据增强是否更接近真实背景
- 模型输出是否还有“直接猜模板”的空间
- grid recovery 是否过重
- 真实 `eval_cases` 上错在哪一层

## 14. 当前建议

第三版最合适的起点不是“大而全”，而是：

```text
piece_map + cross_map + 轻量 grid recovery
```

如果这条最小路线都站不住，再加 `line_map` 才有意义。
